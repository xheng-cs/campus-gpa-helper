# 🎤 面试准备手册

> 配合 [README](../README.md) 与 [PLAN.md](../PLAN.md) 使用。
> 目标：用 5 分钟让面试官觉得你「真的懂自己写的东西」。

## 一、30 秒项目介绍（开场话术）

> 「我做了一个零依赖的校园学业助手网页应用：绩点计算、课程管理、作业待办，数据保存在浏览器本地。
> 它没有用任何框架，但结构是分层的——计算核心是纯函数，配了单元测试，还接了 GitHub Actions，
> 每次 push 自动跑测试。整个项目我走完了『想法 → AI 开发 → 调试 → Git 提交 → 交付』的完整流程，
> 现在可以在线访问（GitHub Pages 链接）。」

## 二、3 分钟技术讲解大纲

1. **问题**：学校查绩点麻烦，手机 App 有广告，做一个打开即用的网页工具。
2. **架构**：`gpa.js`（纯函数计算）→ `app.js`（渲染/交互/存储）→ `test/`（测试）三层。
3. **调试故事**：第一版四舍五入函数有浮点误差，是我补充的边界测试（2.005 → 2.01）抓到并修复的——AI 写的代码同样必须测试。
4. **Git**：语义化提交，一个提交一个主题，每个提交测试都是绿的。
5. **交付**：README、设计文档、CI、面试手册、在线演示。

## 三、高频问题与回答要点

**Q1：为什么不用 Vue / React？**
> 项目规模小，框架反而增加构建成本；零依赖意味着双击就能跑、面试官也能直接看源码。
> 分层设计说明我理解「框架解决的其实是状态与视图同步问题」，如果功能变复杂我会引入框架。

**Q2：localStorage 的优缺点？**
> 优点：同步 API、免后端、刷新不丢。缺点：只有约 5MB、只能存字符串、不能跨设备同步、无法多人协作。
> 如果做多人版，我会换成后端数据库 + 接口，localStorage 只做离线缓存。

**Q3：绩点算法怎么实现的？为什么放在单独文件里？**
> 分段映射表 + 加权平均公式；抽成纯函数是为了脱离浏览器做单元测试，边界（90 / 89.9 / 60 / 59.9）都有用例。

**Q4：测试是怎么写的？**
> Node 内置 test runner，零依赖。举例：解析非法输入、算法分段边界、空数据、脏数据过滤、浮点四舍五入。

**Q5：AI 帮你写了多少？怎么保证代码没问题？**
> 如实回答：需求、设计、验收标准、测试用例、调试和提交都是我把关的；AI 负责生成初稿和解释代码。
> 可以讲浮点 bug 的例子——这正是「人必须在 AI 开发里做质量守门员」的证明。

**Q6：git 你常用哪些命令？合并冲突怎么办？**
> add / commit / push / log / branch / merge / status / diff；冲突时打开文件看 `<<<<<<<` 标记，
> 理解双方意图后保留正确的版本，再 add + commit。

**Q7：如果这个网站有 1000 个用户，哪里会先出问题？**
> 目前数据只在本机，谈不上服务器压力；若做后端，先出问题的会是数据库查询与接口设计，
> 我会加索引、缓存、限流，并用压测工具验证。

## 四、现场演示脚本（约 2 分钟）

1. 打开线上地址（GitHub Pages）或本地双击 `index.html`
2. 点「载入示例」→ 讲解 4 个统计卡片（课程数 / 总学分 / 加权平均分 / GPA）
3. 添加一门课（如：数据结构，4 学分，88 分）→ 指出 GPA 实时变化
4. 切换 4.0 / 5.0 算法 → 说明两种算法的差异
5. 添加一条待办并勾选完成 → 展示过期高亮
6. 点「导出 JSON」→ 展示数据模型设计
7. 打开 GitHub 仓库 → 展示提交历史、README、CI 绿勾

## 五、关于「AI 开发」怎么聊（诚实且有亮点）

- **明说使用 AI，但不心虚**：AI 是生产力工具，部门要求的就是这个流程，说明你紧跟行业现状。
- **强调人的职责**：需求拆解、技术选型、代码审查、测试设计、调试定位、提交规范——这些 AI 替不了。
- **举具体例子**：浮点 bug 是我写测试抓到的；README / 设计文档 / 面试手册是我组织语言写的。
- **工具格局**（可提及）：GitHub Copilot（编辑器补全）、Codex CLI / Cursor（终端 / IDE 智能体）、
  Trae（字节的 AI IDE）、DeepSeek 等国产模型。区别只是交互方式，工作流本质相同：
  **提需求 → AI 生成 → 人审查调试 → 提交**。
